Request DQN policy

The Request DQN is a learned communication policy. It decides which visible vehicle to ask, or whether to ask nobody. It does not directly choose the ego's driving action.

After the DQN selects a request, the frozen MLPx planner uses the returned message to choose the ego action with a three-step planning horizon.

Shared policy design

Request actions

The DQN has nine possible actions:

left-front, left-beside, left-rear,
same-lane-front, same-lane-rear,
right-front, right-beside, right-rear,
ask-nobody

Invalid spatial slots are masked during action selection. The DQN receives a 45-value state representation containing the ego and eight ordered neighbor slots.

ActionFixed request target
0Left-front
1Left-beside
2Left-rear
3Same-lane-front
4Same-lane-rear
5Right-front
6Right-beside
7Right-rear
8Ask nobody

Newly trained DQNs store request_action_encoding: spatial_v1. Empty slots are masked for exploration, greedy selection, and next-state target values. Request resolution, message placement, and the renderer use the same mapping.

This action-mapping correction was made after the first Experiment 3 DQN run. The earlier fix aligned World Model message slots, but DQN actions still indexed the compressed list of visible vehicles. Experiment 1/2 and the first Experiment 3 DQN run retain their original compressed_v0 actions when loaded, with an explicit warning. The latest Experiment 3 DQN was retrained with spatial_v1 actions, reusing the frozen Experiment 3 MLPx checkpoint without recollecting data.

Training setup

DQN reward = real driving reward - communication cost when a vehicle is asked

The DQN uses replay memory, an online Q-network, a target Q-network, epsilon-greedy exploration, and Huber loss. The target network is synchronized every 50 episodes. Each experiment has its own checkpoint and result folder.

Training supports --resume for additional episodes. New latest.pt files contain full training state; older weights-only checkpoints support partial continuation with a warning. See Training for commands and the resume/checkpoint behavior. More episodes do not guarantee higher return or lower DQN loss; compare continued checkpoints on the same evaluation seeds.

Return includes the communication penalty; driving reward excludes it. Request counts are messages sent per episode, so ask-all can send multiple messages in one step.

The DQN has the highest mean return, exceeding ask-nobody by 0.352 (about 2.94%), while sending fewer requests than random or ask-all. However, it crashes in three more episodes than ask-nobody, a difference of 1.5 percentage points. This run shows a small average return advantage, but no safety advantage from communication. Statistical uncertainty has not been quantified, so the return difference alone does not establish a reliable improvement.

All four policies crash in at least 93% of episodes. The shared driving planner and World Model need investigation alongside the request policy; these results do not isolate which component causes the failures.
