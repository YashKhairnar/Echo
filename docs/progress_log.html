Latest milestone

2026-11-19 — Experiment 2 training, evaluation, and intent overlays

  • Collected 197,553 intent-aware and 25,822 random no-message transitions across 1,000 episodes per source; merged them into 223,375 records.
  • Intent-aware rollouts completed 40,000 steps without crashes, using 40-second episodes at one decision per second. The random source contains 526 crash transitions. Collection duration describes this saved run; future runs use the environment configuration at execution time.
  • Trained MLPx for 50 epochs; best test loss was 0.004263 at epoch 42. Three-step no-message evaluation achieved state MAE 0.0213, cumulative reward MAE 0.0422, and 96.55% best-action agreement on 29 valid states. All-message agreement was 68.97%; five-step tests had only 11 valid states.
  • Trained the Experiment 2 request DQN for 1,000 episodes, using its frozen MLPx checkpoint and a three-step planner. Mean training return was 10.263; 984 episodes had the crash flag.
  • Evaluated both experiments on 200 episodes per request policy, starting at seed 100000. Experiment 1 DQN achieved return 14.955 and 92% crashes, versus 13.070 and 99% for asking nobody. Experiment 2 DQN achieved return 12.326 and 94.5% crashes, versus 11.973 and 93% for asking nobody.
  • Experiment 1 currently has better complete-system performance. Short-rollout prediction metrics do not establish safety over full episodes, especially because incomplete candidate rollouts are excluded by the WM evaluator.
  • Added matching MLPx and DQN training graphs for Experiment 2, yellow experiment headings, and dedicated experiment sections in the docs.
  • Recorded Experiment 2 seed 7: crashed at 14/40 steps, driving reward 13.039, and five requests. Its video includes the requested vehicle ID, yellow circle, exact intent response, and ego action. The overlay also appears in future interactive renders and recordings; no-request frames show None.
  • Next investigation: compare imagined and real outcomes near collisions, including early-terminal cases, to explain the high full-episode crash rate.

2026-11-19 — Intent-aware vehicle scenarios and dataset collection

  • Rebuilt the active environment around standard HighwayEnv behavior classes: one controlled ego vehicle plus configurable aggressive and defensive background vehicles.
  • Added stable vehicle IDs and lookup tables for retrieving each vehicle and its behavior type.
  • Limited intent-aware visibility to 60 m, the ego lane, and the immediate left/right lanes. The selector keeps at most eight vehicles.
  • Added get_vehicle_state() for current state inspection and preview_next_action() for calculating a neighbor's next action on a copied road without modifying the real environment.
  • Added smoke tests for messages, visible neighbors, and current state versus previewed action.
  • Added a rule-based intent-aware ego policy supporting all five discrete actions: left, idle, right, faster, and slower.
  • Added request-subset enumeration. For n visible vehicles it evaluates all 2^n - 1 non-empty request subsets, plus an optional no-message scenario.
  • Added counterfactual evaluation on copied environments and JSONL collection of state, requested messages, ego action, next state, reward, termination, and truncation.
  • The initial 100-episode collection produced 4,824 scenario records and 400 counterfactual terminated scenarios (8.29%). This is a scenario crash rate, not the actual full-message policy crash rate.
  • Updated the collector to report counterfactual scenario crashes separately from actual rollout crashes.
  • Replaced the fixed goal-lane behavior with natural lane changes: the ego accelerates until a slower vehicle enters the caution range, then selects a safe left/right lane or slows if neither is safe.
  • Staggered background lead vehicles by lane so the safe escape direction can vary and the dataset includes natural left-lane and right-lane examples.
  • Randomized the lane-to-lead-offset assignment on every reset after the first dataset remained biased toward LANE_LEFT.
  • Added collect_random_no_message_dataset.py, which requests no vehicles and samples random ego actions to collect uninformed safe and crash transitions for World Model training.
  • Merged the intent-aware and random no-message datasets into data/experiment_1/combined_world_model_dataset.jsonl with source labels, source episode IDs, global episode IDs, and unique record IDs: 26,597 records total.

2026-11-15 — MLPx crash head

  • Trained the first merge MLPx (2,000 episodes). It reacted to driver-type messages only weakly; the MLPx planner crashed about 50% of the time with or without messages (scripts/evaluate_merge_planner.py).
  • Added a crash head to MLPx (BCE on terminated), trained the state and reward heads on non-crash steps only, and switched the reward target to the driving reward. Crash AUC on test: 0.96.
  • The MCP planner now weighs each imagined step by its crash probability, and --crash-value sets how bad an imagined crash is.
  • With crash value −6, asking the rear car cut crashes from 21% to 8% (return 4.23 → 4.86), still well below the hand-written ask-rear rule (7.35, 0% crashes).
  • Diagnosis: MLPx predicts the right average merge risk (~45%) and raises it for "aggressive" (65%), but does not lower it for "yielding" (44% vs 0% real). Next: collect more merge data so "yielding" answers are better represented.
  • Collected 8,000 more merge episodes (10,000 total) and retrained: test loss 0.32, crash AUC 0.99. The MLPx planner improved to returns of about 7.5–8.0, but messages now barely change its predictions.
  • Confirmed that the data contains the signal (crash within 3 steps of merging: aggressive 76%, not asked 51%, yielding 31%), so the flat MLPx input is the bottleneck: it must match each car's observation row to its message slot by itself. Next: a per-vehicle encoder that pairs each car with its own message.
  • Replaced the flat MLPx with a per-vehicle encoder that pairs each car's kinematics with its own message (FlatMLPxWorldModel kept for old checkpoints). Test loss 0.286, crash AUC 0.998.
  • First clear message benefit with the learned planner: asking the rear car raised return from 5.21 to 6.53 and cut crashes from 38% to 26% (100 seeds). Still below the hand-written ask-rear rule (7.35, 0% crashes), and the no-message baseline is worse than with the flat model.
  • Remaining issue: crashes happen 1–2 steps after the merge action, so the planner predicts them through imagined intermediate states, which blurs the message's effect. Candidate fix: a "crash within k steps" head.

2026-11-16 — Where the DQN asks

  • Over the three validation-selected DQNs on the 200 test roads:
